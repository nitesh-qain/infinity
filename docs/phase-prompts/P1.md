1. **`memory/schema/graph.schema.json`** — JSON Schema (draft 2020-12), version `0.1`,
   using the prototype field names from the spec. It must enforce:
   - top level: `schema_version` (const "0.1"), `app`, `screens`, `relationships`, `flows`,
     `navigation_index`; no unknown top-level keys.
   - `screens[]`: `screen_id` matching `^scr-[a-z0-9-]+$`, `name`, `sample_urls` (array of
     URLs), `elements[]`.
   - `elements[]`: `element_id` matching `^el-[a-z0-9-]+$`, `label`, `type`, `action`,
     `navigates_to` (a screen_id or null), `locators` (non-empty, ordered), `last_verified`
     (date, `YYYY-MM-DD`).
   - `locators[]`: `strategy` in `role | testid | text | css`, `value`, optional `name`
     (accessible name, used with `role`).
   - `relationships[]`: `rel_id` matching `^rel-[0-9]{3,}$`, `screen_id`, `type`, `source`,
     `target`, `test_hint`. `type` is an enum of exactly the 11 labels in the spec.
   - `flows[]`: `flow_id` matching `^flow-[a-z0-9-]+$`, `name`, `steps[]` of
     `{ screen_id, element_id, action }`.
   - `navigation_index.edges[]`: `{ from, via, to }` (screen, element, screen).
   If the spec is silent on a field's exact shape, ask me rather than inventing it.

2. **`scripts/validate-memory.ts`** + npm script `validate:memory` (use `ajv` +
   `ajv-formats` as dev dependencies). It takes a graph file path (default
   `memory/graph.json`) and checks:
   - schema validity;
   - IDs are unique (screens, elements, relationships, flows);
   - every reference resolves: `navigates_to`, relationship `screen_id`/`source`/`target`,
     flow steps, navigation edges;
   - locators are in the ranked order role → testid → text → css.
   It prints each problem with its JSON path and exits non-zero on any problem.

3. **`memory/labels.md`** — the 11 core labels as a table (label · meaning · check pattern
   · origin), copied from the spec, plus a short section "Proposing a new label" stating
   the rule: a new label needs its check pattern and my approval, and the schema enum is
   updated only after approval.

4. **`memory/pages/_template.md`** — the page-file template: screen_id, purpose, business
   rules (each rule referencing element IDs only), open questions for the QA team. Include
   one filled example rule as a comment so the format is clear.
